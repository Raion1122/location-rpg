# 出力フォーマット

会議は 2 段階。各段で出力テンプレートが異なる。どちらも「① 対話ログ」を主役にしつつ、末尾で慶彦さんにボールを返す。

---

# 第1段：発散会議の出力

## ① 発散議論パート（対話ログ）

```
# 開発会議〔第1段：候補出し〕：{議題}

**議題**: {1〜2行}
**ゴール**: 毛色の違う実装候補を出して、進む方向を1つ選ぶ
**会議の前に測ったこと**: {1-0 で確かめた事実を箇条書きで数件。崩れた前提があれば明記}

---

## 第1ラウンド：ブレスト（各専門領域から方向性を1つ）

【ガイウス】{冒険の中身（依頼・ダンジョン・物語）の方向性}……
【レンツ】{仕組み（戦闘・成長・装備・保存・サーバー）の方向性}……
【ミサキ】{地図と見た目（人形・入口の絵・演出）の方向性}……
【ノエル】{歩きやすさ・手触り・安全の方向性}……

## 第2ラウンド：絞り込み（制約で間引く）

【ノエル】{歩きながら・スマホ実機・安全の目線で却下や懸念}……
【レンツ】{使い回し可否・工数・歩かずに試せるか・素材ルートで間引き}……
...
```

**書き方**: 1 発言 2〜5 文。深掘りしすぎない（深掘りは第2段）。幅を出すことを優先。

## ② 候補一覧（決裁用・第1段）

```
---

# 🎲 実装候補（方向性を選んでください）

## 候補①：{名前}
- **ジャンル**: {冒険の中身／仕組み拡張／地図・見た目／歩きやすさ・QoL 等}
- **狙い**: {1行}
- **ざっくり規模**: {小／中／大}
- **使い回し度**: {高／中／低}（{使うもの。例: quest.js の REQUESTS に行を足す}）
- **歩かずに試せるか**: {地図ツールのピンで全部試せる／一部は現地が要る（何が）}
- **スマホ・安全**: {クリア／要注意（理由）}
- **推し**: {誰} ／ **慎重**: {誰}

## 候補②：……（別ジャンル）
## 候補③：……（別ジャンル）
## 候補④：……（任意）

---

➡️ **どの方向性を進めますか？** 選んでいただければ、その案に絞って実装会議（第2段）を開き、開発計画書を作成します。
（番号で指定／複数気になる場合は相談も可／別議題に変更も可）
```

**第1段の鉄則**:
- 候補は**ジャンルを散らす**。似た案を並べない。
- ここで止める。**勝手に第2段（開発計画書）へ進まない。**
- スペックは軽め。細かい工数・リスクは第2段で詰める。

---

# 第2段：収束会議の出力

慶彦さんが候補を 1 つ選んだ後に実行。

## ① 実装議論パート（対話ログ）

```
# 開発会議〔第2段：実装計画〕：{選択された案の名前}

**選択案**: {候補の番号と名前、1〜2行で再提示}
**ゴール**: この案を実装に落とす開発計画書をつくる

---

## 第1ラウンド：設計

【レンツ】{どのファイルのどの仕組みを使い回し、何を新規に作るか。複数ファイルに足す所。保存の形。server.js の起動し直しの要否}……

## 第2ラウンド：肉付けと衝突

【ミサキ】{地図の見た目・必要な絵}……
【ガイウス】{冒険の組み立て・危険度と報酬の釣り合い}……
【ノエル】{歩きながらの手触り・GPS のブレ・置き場所の安全・エッジケース}……
（ここで最低1つ対立→折衷で着地）

## 第3ラウンド：合意

【レンツ】{実装順序・フェーズ分割・素材調達の段取り・歩かずに確かめる手順}……
...
```

---

## 共通の原則

- **対話ログを主役に**: 読み物として楽しめる議論にしつつ、決裁パートは走査しやすく。
- **正直さ**: 弱点を隠さない。全案を等しく持ち上げない。
- **段ごとに必ず止める**: 第1段は選択待ちで止め、第2段は計画書を出して修正待ちで止める。エージェントが勝手に先へ進めない。
- **過剰な装飾を避ける**: 絵文字は見出し程度に留める。
